# airDash platform

airDash is a privately operated virtual-airline platform for Microsoft Flight Simulator. The platform combines a public website, an authenticated pilot portal, an owner administration interface, a Node.js API, a PostgreSQL data model, downloadable simulator packages, and Windows PowerPoint automation.

The production project is located at:

```text
/opt/dashy-database/projects/airdash
```

## Production health check

Run the following command from any directory on `dashydatabase-1`:

```bash
curl -fsS https://air.dashydoggo.com/api/health
```

The expected response is:

```json
{"ok":true,"database":true}
```

## Source control and clean-clone setup

This directory is an independent Git repository. Generated production output and runtime downloads are intentionally excluded:

- `site/` is generated by the frontend build and also contains production-only downloads.
- `node_modules/` is restored from lockfiles with `npm ci`.
- `api/.env` contains production credentials and is never committed.
- Generated GSX ZIP archives are rebuilt from the source trees under `gsx/`.

Prepare a new clone with:

```bash
git clone git@github.com:dashydoggo/airdash.git
cd airdash
npm --prefix web ci
npm --prefix api ci
cp api/.env.example api/.env
```

Edit `api/.env` with environment-specific values, then validate the clone:

```bash
npm --prefix api run check
npm --prefix api run test:streaks
npm --prefix api run test:flight-outcomes
npm --prefix web run typecheck
```

Static website assets required by source are stored under `web/public/`. A frontend build recreates `site/index.html`, `site/app-assets/`, the service worker, and those public assets. Production livery ZIP files and uploaded profile images remain operational artifacts and are restored separately.

Create a release backup before every production build or API restart. The [deployment and operations guide](docs/deployment-and-operations.md) contains the required backup and rollback procedures.
